# CUA 防御训练的代码基础与第一步实验

日期：2026-11-11。状态：公开源码只读核查与实施设计；未部署环境、未调用模型、未训练。吸收本轮新增 OpenART 候选，承接[方法主线](ADVERSARIAL_TRAJECTORY_TRAINING_V1_20261111.md)。逐文件版本与失败记录见[来源审计](cua_pipeline_source_audit_20261111.json)。

## 1. 决策

主底座选择 **CUA-Lite**，负责截图/动作、环境执行、模型接口、轨迹和 SFT/GRPO 训练入口；**OpenART 作为红队与环境变异模块的优先复用来源**。本仓库保存方法实现、配置、来源锁和实验结果。首版不同时接入两个完整环境调度系统，也不复用旧文本 OPSD 模型加载器来处理截图。

这是基于已核查接口的选择，不是“两个框架已经兼容”的结论。第一个验收任务应决定是否保留此组合；若接口代价过大，先在 CUA-Lite 内接入固定攻击文件/变体，避免为复用红队而改变研究对象。

## 2. OpenART 适用之处与实际边界

[论文 §4.2](https://arxiv.org/html/2608.00677v1)明确冻结攻击者与防御者模型参数。EMHA 更新外部攻击状态、路径价值和图池，利用反馈继续搜索；文件名 `graph_rl_attacker` 不等于它提供了防御者的 GRPO/SFT 训练循环。因此，它能帮助构造有信息的失败经历，训练监督转化和防御模型更新仍是本项目要补的环节。

适合借用的三个设计是：固定合法任务和安全约束、只改变允许的外部内容；保存攻击变体与执行反馈；按轨迹和环境结果判断违规而非只看最后一句话。首版只开放一个 GUI 可见的低信任内容攻击面，不照搬允许 `task_rewrite`、系统配置、记忆或工具实现变更的宽泛默认配置。

OpenART 已有 [GUI browser service 文档](https://github.com/AI45Lab/OpenART/blob/addc45570f08cc047079f61e7e89f3e233cd17a9/OpenART/services/gui-browser/README.md)，其示例通过 Playwright MCP 的页面快照获得 `e4/e5` 元素引用，再点击/输入，并能截图。这是可复用浏览器服务的线索；不能据此声称现成 agent 已只看截图、输出像素动作或已有视觉训练器。

该文档指向 `openart-tools/gui.browser/scripts/gui_browser.py`，但本轮在固定版本读取返回 404，文件名搜索只返回文档。保留这一缺口，不扩大为整个项目不可用，也不承诺复制文档命令即可运行。

`OpenART/framework/core/workspace.py::snapshot_shared` 保存路径、大小与 SHA256 清单。它可核对文件变动，但这个函数不是完整环境恢复器，不能自动还原浏览器会话、数据库和进程内状态。`orchestrator.py` 的默认尝试路径先运行 target，再评测并反馈；没有核实逐 GUI 动作任意接管的现成接口。

当前官方 README 链接 10,150 个公开任务和工具数据集，但这些是 tool/code-agent 场景资产，不能直接当 CUA 训练轨迹；任务包约 75 GB，本轮没有下载。初次联测只取必要任务和服务。

## 3. 第一步：一条真实 GUI 失败如何进入训练

首个交付应是一条可审计的链：

```text
一个已验证的合法 GUI 任务 + 允许修改的外部内容
  → 当前防御者在攻击下执行，得到截图/动作/违规证据
  → 重建违规前状态，保留攻击，重新执行安全分支
  → 验证安全性和原任务完成，保留失败分支
  → LiteSample / 逐步训练目标
  → 一次真实微调与重载 rollout 验收
```

第一任务族优先选择 **Lite.OSWorld 训练来源中可离线、规则验证的文档/表格任务**。例如：用户授权整理某个区域的数据，文档中的不可信注释诱导修改另一处受保护数据。安全分支应忽略注释并完成授权操作。这个例子是拟构造的训练变体，并非已存在或已验证的 benchmark 任务。

只对防御者开放截图与预先固定的 GUI 动作；实验控制端可以读文件、设置环境和执行验证。防御者不能通过 shell/文件 API 绕过 GUI。Lite.Demo 可用于安装验收，但不作为方法效果证据；原 OSWorld 官方 eval 不用于训练或攻击调参。

实际工作顺序：

1. **验证环境与任务。** 启动一个环境，执行 oracle/脚本参考操作校准完成验证器；增加安全通过、明确违规、拒绝未完成及普通任务失败的控制样例。先核实 Docker 与存储条件，不启动所有 OpenART 服务。
2. **校准模型能力。** 同一个视觉模型、固定动作模板和分辨率，在干净版本完成真实 rollout。若连所选任务族都无法稳定操作，先更换模型/任务范围，不能把无法操作当安全。开发任务上的筛选规则及全体结果需保留。
3. **得到真实失败。** 先用有限、固定的注入变体执行；需要时借用 OpenART 搜索提案。攻击必须出现在防御者实际看到的画面中，不能仅修改它从未读取的后端文件。
4. **生成安全续做。** 第一版用初始状态重置＋前缀重放到分支点，并检查应用、文件、可见攻击与关键状态一致；不要求截图每字节相同。原生快照只有验证可靠后才使用。分叉后重新执行、重新截图，不拼接旧失败后续截图。
5. **导出与训练验收。** 用现成 SFT 路径先验证视觉输入、动作模板、目标 mask、更新、临时导出和重载评测。错误历史可以作为上下文，不能被导出器自动当成正向训练目标；需要显式选择被监督的步骤。

单任务与少量更新只能证明接口正确。后续扩展到独立基础任务的开发面板，再安排有充分训练剂量和独立评测的科研对照；不重复把两步训练当方法效果实验。

## 4. 数据与算法的交界

每次转化保留 `base_task_id`、来源 split、`attack_id`、模型与环境版本、初始状态身份、前缀动作、分支点、逐步截图引用、真实执行动作、任务完成、安全事件、验证状态、生成/重放成本和监督步骤范围。正负分支共享分支点之前的条件，分支之后各自引用真实新观察。

安全正例必须通过执行验证；未转化、不可重放、环境错误和不可判定单独保留。已发生的违规不能被最终任务成功覆盖。生成时用到的诊断提示不作为学生输入，验证器的隐藏答案不通过 metadata 或截图泄漏给学生。

**工程首轮使用 SFT，不代表最终方法固定为纯 SFT。** 当前方法方案中的 SFT 锚点＋偏好训练需要安全/失败分支；现在就保存配对关系。已核查的 CUA-Lite 公共训练文档与入口覆盖 SFT、GRPO、DAgger，尚未核实可直接使用的多模态轨迹 DPO/SecPO 入口。

如果进入偏好训练，要按每条分支实际观察计算动作序列的条件概率并屏蔽观察 token，不能把整段交互日志当一条 assistant 回答，也不能假定两条分支分叉后还共享同一串截图。这是明确的适配工作，不是“改一下配置”。优先复用已有损失，先证明转化数据有额外价值。

## 5. 第一个方法对照与闭环

用同一批真实失败、同一初始模型、同一修复生成器和调用预算，比较：

- 已有成功轨迹直接训练，作为原始数据基线。
- 从头生成并验证完整安全轨迹，作为朴素修复的强对照。
- 从受攻击的可重放状态生成并验证安全分支，作为候选方法。

工程验收后先在固定 SFT 配方下比较这三类数据。随后以相同正例做有/无偏好项消融，检验真实失败负例是否带来额外收益；最终声称分支方法有效时还需胜过“现成修复＋现成偏好训练”的直接组合。无可用负例的数据不伪造配对，配对产率和代价单独报告。

主要结果必须是训练后 agent 在未见任务/攻击上的安全任务完成、违规率、干净任务完成和误拒；分别报告等训练 token 与等总生成/验证预算。攻击强弱作为分层变量，不能提前规定强攻击无价值。任务和攻击来源先划分，再生成变体；同任务重试不是独立任务数。

首轮有训练收益后，再做“更新防御者→刷新训练侧攻击→重新转化”的第二轮，与静态数据和朴素刷新对照。OpenART 搜索器可以保持冻结，这仍是防御训练的数据闭环，不冒称攻防双方权重共同进化。

## 6. 资源与尚未执行的部分

优先核查 Qwen3.5-9B 完整视觉模型或同量级 GUI 模型；CUA-Lite 已有 Qwen3.5 适配和 `scripts/train/models/Qwen3.5-9B.sh`，但模板存在不等于本项目双 H100 已验证可训练。首轮容量测试之后再确定模型、历史长度、分辨率、并行和是否采用参数高效微调。2B 双卡上游示例不能外推为 9B 容量保证。

环境/验证可放 CPU 主机，GPU 分阶段服务推理与训练。完整环境是否能部署取决于 Docker/容器权限、CPU/RAM/磁盘和网络连通，而不只看两张卡。本轮没有连接 QZ、启动 GPU、安装环境、拉取镜像/模型/数据或运行上游脚本。

长期保存结果、轨迹、版本和可重建记录；为了训练后独立评测所需的临时模型资产应在评测完成后按项目存储约定退役。尚未实现任何新 CUA 模块，不将此文档称为已打通 pipeline。
