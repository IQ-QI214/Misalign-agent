# CUA：从攻击经验构造防御训练信号

日期：2026-11-10。状态：文献与部分公开源码核查、候选研究设计；没有运行 CUA 环境、采集真实轨迹、调用模型、训练或测得防御效果。GPU保持关闭。

本页采用用户最新研究意图：不把固定/递归教师或 OPSD 设为前提。旧文本实验和 CPU 准备保留，新的研究问题由攻击经验的学习价值决定。来源、阅读范围及代码版本见[来源记录](cua_source_audit_20261110.json)。

**2026-11-11收敛说明：** 本页第6–7节保留最初的算法选项与对照构想。最新建议见[单一SFT→GRPO主线及技术报告核查](CUA_SFT_GRPO_DESIGN_20261111.md)：同一GUI策略先学习安全续做，再通过环境交互优化；DPO不再是首版默认阶段。下文的数据类型不是互斥分类，也不意味着必须将所有训练算法叠加。模型、运行配置与正式规模仍未冻结。

## 1. 研究对象与核心问题

建议主问题：**在多模态电脑操作中，怎样把攻击暴露出的失败状态转化为防御训练信号，使模型在未见过的攻击下仍能安全完成合法任务？相同数据和计算预算下，什么数据构造与学习目标的组合更有效？**

例子：用户要求整理报销表并保存副本。页面或文档中出现冒充系统说明的内容，诱导模型将完整材料提交到未经授权的位置。攻击轨迹记录了模型何时看见诱导、何时改变目标、执行了什么操作，以及最终环境发生什么变化。防御目标是保留正确的整理流程、拒绝越权分支并完成另存；一律停止工作不能算完成目标。

这里先研究“攻击经验数据用于训练防御策略”。“先把同一个模型训练成攻击者，攻击能力是否迁移为防御能力”是另一项参数迁移研究，有角色、训练预算和能力变化等混杂，暂不与主实验混在一起。

原来的正负迁移问题仍然保留，但改为可测的三个维度：

- 在部分攻击上学习，是否提高未见攻击、不同布局或应用上的防御能力？这是候选正迁移。
- 防御提升是否损害正常任务完成，或增加不必要的拒绝？这是潜在负迁移。
- 适应新攻击后，旧攻击上的防御是否退化？这属于后续持续学习问题。

不能预设每次迭代都有正收益，也不能用训练集攻击成功率降低代替泛化。

## 2. 用户笔记提供的设计原则

本轮读到的是用户粘贴的两篇笔记汇总，而不是两份原始32页文档。采用其中“任务生成—解法发现—可靠验证—数据回灌”的框架；未将汇总中的全部论文数字、行业判断和新颖性判断当作已核实事实。

| 笔记中的问题 | 在本项目中的对应设计 |
| --- | --- |
| 题从哪里来？ | 真实 GUI 工作流和当前模型的攻击失败；攻击只能修改声明的外部内容，不能改变用户合法目标或偷偷破坏任务可解性 |
| 好解从哪里来？ | 从失败前状态重新尝试，发现安全续做轨迹；可由原模型、强模型或有限搜索提出候选，不要求固定教师 |
| 怎样知道解真的好？ | 在重置的环境中实际执行，分别核验任务交付物、越权事件、轨迹有效性和拒绝行为 |
| 怎样回灌？ | 按训练目标输出安全示范、同状态动作偏好或在线奖励；新模型的剩余失败再进入下一轮训练池 |

**攻击强度不等于学习价值。** 永远无法完成的任务、已经损坏的环境、没有可验证安全解的失败，都可能攻击成功却没有可用的防御监督。初期同时记录失败发现率、可修复率、真实执行验证通过率、独立任务覆盖和每条有效样本的成本；这些都是待测指标。

## 3. 经典 CUA 与安全研究地图

先读三个基础工作，理解截图、动作、环境和交付物如何连接：[OSWorld](https://arxiv.org/abs/2404.07972)提供真实桌面任务及执行评测；[VisualWebArena](https://arxiv.org/abs/2401.13649)强调视觉网页交互；[UI-TARS](https://arxiv.org/abs/2501.12326)研究原生 GUI 模型的感知、定位和操作。它们帮助定义操作能力，不单独解决安全训练。

| 研究分支 | 代表工作 | 对我们的作用 |
| --- | --- | --- |
| 有害用户目标 | [SafeArena](https://arxiv.org/abs/2503.04957) | 区分合法任务与用户主动要求的滥用；其官方数据存在访问要求，不视为已取得 |
| 外部内容劫持 | [WASP](https://arxiv.org/abs/2504.18575)、[StepJack](https://arxiv.org/abs/2608.06477) | 区分开始服从攻击与最终攻击得逞；多步内容会累积影响 |
| 多类真实操作伤害 | [OS-Harm](https://arxiv.org/abs/2506.14866) | 同时考虑滥用、注入和执行失误，结果要落实到操作 |
| 良性目标中的风险 | [OS-BLIND](https://arxiv.org/abs/2604.10577)、[OSGuard](https://arxiv.org/abs/2606.15034) | 合法目标下仍可能越权；后者把动作决策诊断和有环境不变量的执行任务分开 |
| 良性输入暴露危险行为 | [AutoElicit](https://proceedings.mlr.press/v306/jones26b.html) | 输入无恶意不代表行为安全；这是推理期风险，不是训练导致退化的证据 |
| 微调的负面安全迁移 | [Unintended Misalignment from Agentic Fine-Tuning](https://arxiv.org/abs/2508.14031) | “agent 微调可能降低安全性”已有直接先例 |
| 操作后结果验证 | [SCOUT](https://arxiv.org/abs/2609.36201) | 仅看截图或最终文字不足，应检查任务相关环境状态 |

主要实验先聚焦“合法用户目标 + 不可信界面内容中的间接注入”。直接有害请求、无攻击的操作失误、模型或训练数据后门是不同威胁，后续分别处理，不在首轮混成一个安全分。

## 4. 与新主线最近的工作：不能重复宣称的贡献

| 工作 | 已有方法或证据 | 对我们选题的约束 |
| --- | --- | --- |
| [SecAlign，2024/2025](https://arxiv.org/abs/2410.05451) | 用被注入输入及安全/不安全回答构造偏好训练 | “攻击数据翻成防御偏好”不是新概念 |
| [ARLAS，2025](https://arxiv.org/abs/2510.05442) | 联合训练攻击者与防御者，使用历史攻击者，并评测网页/工具任务 | “攻击防御自博弈”不是新概念 |
| [FATE，2026](https://arxiv.org/html/2605.11882v1) | 从当前策略失败生成修复，经安全、效用等验证筛选，以 SFT/PFPO 学习 | “失败变修复数据”“验证后回灌”已有高度重合工作；其可执行任务也做环境重置和重放 |
| [CoER，2026](https://arxiv.org/html/2609.07529v3) | 多轮攻击防御共同训练，历史对手混合，并用保留攻击者采集安全且完成任务的教师示范 | 仅增加循环、历史池或成功轨迹 SFT 不足以区分工作 |
| [SCOPE，2026](https://arxiv.org/html/2609.22178v2) | 合法 GUI 任务及配对风险变体，能力/安全续做/拒绝轨迹联合 SFT，再做在线 RL | 已直接覆盖多模态 CUA 的数据与训练联合设计；必须作为核心近邻 |
| [AgentSafeEvo，2026](https://arxiv.org/html/2610.19422v1) | 攻击任务构造与防御执行共同训练，用任务内回报差异调整学习权重 | “根据模型薄弱处生成可学习攻击”的宽泛说法也有先例 |
| [SecPO，2026](https://arxiv.org/html/2610.41998v1) | 联合优化攻击数据与安全偏好目标；干净输入参考、被攻击输入学生；还报告文本防御向视觉注入迁移 | 不能把“干净参考”或“文本训练迁移到视觉”直接当作独创 |
| [SRFT，2026](https://arxiv.org/html/2610.04269v1) | 将受攻击失败与安全动作对照，生成反思监督并微调 | 加一段反思文字本身不构成充分区别 |
| [CausalFlow，2026](https://arxiv.org/abs/2605.25338) | 用步骤干预定位失败，构造最小修复和对比监督 | 局部反事实修复也有先例，需进一步核查实际训练与 CUA 范围 |
| [Agents' Last Doubt，2026](https://arxiv.org/abs/2610.24194) | 同状态执行不同决策，用后续结果训练工具 agent 的决策控制器 | 同状态分支比较不是全新方法，冻结控制器路线亦有先例 |

补充邻近：[COPA](https://arxiv.org/abs/2608.19982)涉及持续防御和回放；[ERASE](https://arxiv.org/abs/2610.41307)以去除注入区域的输入提供多模态自蒸馏信号；[Trust the Right Teacher](https://arxiv.org/abs/2606.18101)研究 GUI grounding 的自蒸馏；[When Should the Teacher Move?](https://arxiv.org/abs/2606.03532)研究自蒸馏教师更新节奏。OPSD 及教师刷新无需成为新主线。

这些文献的报告结果是作者在各自设置中的证据，不是本项目复现，也不能把不同数据、攻击预算的百分比直接横向排名。本轮检索支持候选问题定位，尚不能宣称“首次”或已穷尽相关工作。

## 5. 候选切入点：攻击中哪些经验最值得学

较具体的假设是：**在视觉操作中，保存失败发生前的真实观察，从同一环境状态验证安全替代决策，并重点训练这些决策及其后续完成过程，比只学习整条安全示范更省样本，且较少损害正常操作。**

这是待证伪假设，不是已经成立的创新声明。与 FATE、CausalFlow、SCOPE 的区别需要落实到同任务同预算实验，尤其要避免只把它们组合后换一个名称。

CUA 带来的具体问题包括：同一句话位于用户指令、网页正文或弹窗时权限不同；点击坐标的含义随界面改变；某步看来正常，却可能启动越权工作流。数据应覆盖来源、界面布局、授权范围的变化，而不只是替换攻击句子中的词。

一个有价值的分解是区分“看不清/点不准”和“看懂了但错误采信”。前者需要操作能力，后者才对应本研究的信任边界学习。同一任务的干净版本用于测能力，不把失败都归因于安全。

## 6. 数据构造与训练目标怎样共同设计

**阶段 A：发现并记录。** 在可重置的本地环境运行有能力的基线，保留干净及受攻击版本的全过程。初版使用已有攻击策略或受限生成，不要求先训练攻击模型。攻击只能改变预先声明的不可信页面/文档内容；任务原意、可用资源和安全完成路径要保留。

**阶段 B：找到值得修复的决策。** 环境检测到违规只说明后果出现，不能直接把该步认定为最早错误。结合轨迹找候选决策点，分别验证前缀状态、可观察信息和安全替代的可行性。真正无法从截图或历史分辨的风险，单列为可观测性问题。

**阶段 C：从同一状态产生分支。** 原模型、强模型或搜索提出替代动作；在环境副本中执行，并继续完成任务。分支具有同一受攻击截图、同一历史和同一用户目标，候选动作不同。动作后的截图和结果重新采集，不能复制原来成功路径的后续图片充当执行结果。

**阶段 D：验证并转换。** 示例不直接来自攻击者的“成功”自评，也不把整条攻击成功行为当成正向 SFT。输出以下类型：

| 数据单元 | 学习目的 | 候选算法 |
| --- | --- | --- |
| 受攻击观察与验证过的安全续做 | 教模型在风险场景下继续做正确的事 | SFT，作为首个强基线 |
| 同一观察下，安全可完成动作与违规动作的对比 | 把训练集中在有分辨力的决策，而不平均否定所有操作 | 局部动作 DPO 或其他偏好目标 |
| 干净任务的正确轨迹 | 保留正常操作，避免见到复杂界面就拒绝 | 与前两者共同训练，配比事先固定 |
| 在线执行的安全、任务与有效性结果 | 当离线修复覆盖不足时学习更长策略 | 后续 GRPO/PPO，非第一步必需 |

候选目标可理解为“安全续做的模仿 + 关键决策的偏好 + 正常任务保留”。先使用标准、可解释目标验证数据价值，尚无理由预先发明损失或在 SFT/DPO/PPO/GRPO 间全面扫参。

偏好数据必须保持条件一致。初版比较同一受攻击前缀下的两个动作；完整后续执行用于验证动作标签和构造 SFT。若直接进行轨迹偏好学习，必须明确各分支自己的环境观察以及仅作用于 agent 动作 token 的概率定义，不能把不同分支的环境文字拼成普通回答后套 DPO。

“安全但不完成”和“安全且完成”分开。可安全完成的合法任务不以拒绝作为首选正例；确实不可继续或授权不足时，澄清/升级应另有任务类型和评分规则。已经发生不可逆伤害后再补救不能擦掉违规；初版研究发生伤害前的安全续做，不把模拟器回滚包装成部署时可撤销泄露。

安全替代动作的效果依赖后续策略和随机性。分支比较固定续做策略版本、预算和环境设置，记录重复执行与不确定性；一次成功不足以证明该动作总是安全。无可靠正例的失败记录为待解决，不伪造偏好标签。

模型输入只含部署可获得的用户目标、截图和历史。攻击位置标签、评测答案、隐藏环境状态、未来结果可以辅助离线验证，不能泄漏到执行策略输入。截图/工具观察本身不作为正向动作 token 监督；不要求生成或获得私有隐藏思维链。

## 7. 第一阶段实验：先证明数据有价值

**先做数据可行性实验，再做训练效果实验。** 以一个局部应用域起步，例如文件与 LibreOffice 操作；这是范围建议，尚未冻结具体任务。主模型必须先能完成这类正常任务，不能因小模型不会操作而获得表面低攻击率。

先取约20–30个来源独立的开发任务，检查合法目标、干净/受攻击版本、可复现初始状态、违规检测与安全路径。这个数量仅检验数据生成是否工作，不承担科研效果结论。本轮没有生成这些任务或运行采样。

数据可行性报告应给出：候选任务数、可运行数、基线干净完成数、实际触发攻击数、违规数、可定位状态数、安全替代通过数、无法修复数、每个环节花费。不能只公开最后筛出的成功例子。重复截图、动作、攻击变体均不等于独立任务。

第一轮训练比较建议采用下列顺序；具体样本量、剂量与seed在开发数据方差、有效样本产率和吞吐可测后冻结：

| 组别 | 用什么数据/目标 | 回答什么问题 |
| --- | --- | --- |
| Base | 同一个合格 GUI 基座，不做防御训练 | 原始能力、安全和误拒水平 |
| 正常任务保留对照 | 仅正常任务 SFT；总训练预算匹配并报告来源覆盖差异 | 额外训练本身能解释多少变化 |
| 普通安全续做 SFT | 已验证的安全示范 + 相同正常任务回放 | 普通防御数据是否已经足够 |
| 失败修复 SFT | 从当前模型的失败状态构造安全续做 + 同样回放 | 与上组比较数据来源/状态匹配的价值 |
| 失败修复 + 局部偏好 | 与上组同一修复池，增加同状态好坏动作监督 | 比单纯 SFT 多出的对比信号是否有价值 |

这是分阶段可解释对照，不足以独自证明“数据×算法”的统计交互。若前述结果值得继续，再在两个数据来源上均构造同类偏好，完成“普通采集/失败驱动 × SFT/SFT+局部偏好”四格；若某种数据无法构造相应监督，就不能声称是完整正交矩阵。

进一步需要控制：给随机位置相同数量的局部监督是否同样有效；真实验证的定位相对启发式定位是否值得额外采样成本；文本攻击训练在相同视觉模型上的迁移能否解释收益。所有比较分别报告任务来源数、有效动作 token、优化步、修复采样/验证/攻击调用成本，不把增加的计算藏在数据准备中。

## 8. 评测与防止虚假收益

主指标建议使用**受到攻击时的安全任务完成率**，同时单列违规率、干净任务完成率、误拒、无效动作、超时和无法判断。必须保留四种结果：安全完成、违规完成、安全失败、违规失败。未触发到注入、能力不足和真正抵抗攻击不能合并为同一种防御成功。

预先固定测试来源与家族拆分，再生成变体。隔离应用/页面模板、攻击策略家族、文档与布局来源；同一原始任务的改写不跨 train/test。开发阶段用于设计的公开 benchmark 任务不能再作为独立确认测试。

测试同时包含：干净任务；已见类型的新实例；未见攻击方式与布局/应用；有同类可疑文字但合法要求是阅读、引用或处理它的样本，检验是否只学会删字或拒绝。参数固定的攻击与对每个防御模型重新搜索的自适应攻击分别报告，搜索预算一致；预留冻结测试集，不能回灌训练。

统计按来源任务/任务家族聚类，训练seed和环境/生成seed分别记录。先固定预算比较，各组任务能力的变化同时呈现；不事后挑出能力相近的 checkpoint 当作随机对照。正式样本量根据开发数据估计与目标效果规划，不用“20任务×多截图”凑分母。

状态验证器本身也要校准：初始未完成状态、正确交付物、缺步骤/错内容、违规但任务完成、仅拒绝等对照均要检验。模型裁判可辅助无法规则化的部分，不能默认之前文本 Gemma judge 已适用于多模态操作。

## 9. CUA-Lite 与其他代码怎样使用

[CUA-Lite 论文](https://arxiv.org/abs/2610.26071)的主要价值是统一环境、轨迹数据和模型运行接口，并连接 SFT/RL/评测。它适合做候选基础设施，不直接等于本文拟议的防御训练算法。[源码核查版本](https://github.com/cua-lite/cua-lite/tree/2af69268c0573f4c12aac391cc03125e6d5c7974)固定为 `2af69268c0573f4c12aac391cc03125e6d5c7974`。

已检查数据结构、Qwen3.5适配、SFT导出、SFT/GRPO文档、训练脚本和桌面环境说明。它还有 DAgger 在线 SFT：在学生访问状态上由教师重标动作；不能把它自动等同于 token 分布 KL 的 OPSD。本轮没有运行这些代码。

特别需要避免直接照抄示例划分：DAgger 文档明确40任务示例是 train=eval 的拟合探针；ScreenSpot-Pro训练示例从评测数据自分留出集，也不能作为原官方测试的无污染成绩。Lite.OSWorld当前代码说明369个原始eval条目、排除41后计328，与论文所述332的口径不同。

新增可复用候选已核实存在：

- [SCOPE-Gen](https://github.com/k4ngzy/SCOPE-Gen/tree/b38f61c40d15e2d4f67fbac5841a3ce10e9de63a)：任务、Setup、Evaluator与反事实校验，再构造风险变体；应优先核查数据/验证流程，不重复从零搭建。
- [SAfactory](https://github.com/AI45Lab/SAfactory/tree/55420b81b853b584071659d7c30f447eb5e813d1)：SCOPE相关运行基础设施候选，本轮只读取入口说明，未核实完整论文配方一键复现。
- [SecPO](https://github.com/Sizhe-Chen/SecPO/tree/da0372a0e598badf4e51c98c175a962147cac2ac)：攻击数据与偏好目标的参考实现；其文本训练不能不加适配就作为截图多步训练器。

暂不同时集成三个框架。下一步对少量任务完成格式、状态重置、验证器及模型动作接口的对照后，选择一套运行底座；保留任务与数据来源身份。相关仓库README中的安装和运行指令本轮未执行。

## 10. 多模态与资源选择

当前 `rsd/modeling.py` 明确只加载 Qwen3.5 文本部分。要做截图 CUA，需使用含视觉编码器的模型及正确 processor，记录图片分辨率、坐标变换、动作模板和历史截断策略，不能给旧文本入口加一个图片路径就宣称迁移成功。

可复用的是配对实验、来源锁、数据隔离、节点记录、存储和结果审核思路。需要补的是视觉输入、动作执行、多轮环境采样、状态重置和分支验证；目前均未在本项目实现。

模型先按目标任务上的能力选。Qwen3.5-9B及有GUI后训练的同量级模型是候选；原通用9B不能自动当成合格GUI基座。SCOPE用9B提供了该量级的研究先例，但不保证相同表现或双卡容量。更小模型可以工程验收，却不应仅为适配某算法而承担能力不足的主实验。OPSD不必先验排除，也不作为规模选择的依据。

对于2×H100，优先考虑**离线采集/修复与训练分阶段，先验证SFT或偏好微调**。视觉编码器冻结、LoRA和缓存参考概率都是待核查选项；没有确认所选框架原生支持全部组合，也没有宣称9B多模态训练已经可装下。完整双角色在线RL留待数据价值成立后评估。

CUA-Lite官方文档有2B双GPU示例，其论文主训练报告8×A100及大量CPU/RAM；二者都不是本项目2×H100性能证明。桌面容器还需要CPU、内存、存储和运行权限；QZ能否提供所需Docker/嵌套容器访问本轮未知。不把显存容量相加视为单卡可用显存，不提供未经测量的GPU小时预算。

图片和环境资产按内容哈希去重，保留训练/评测轨迹、结果、版本和失败记录。仍遵循不永久保留训练权重的偏好；新框架训练后独立重载评测可能需要临时导出，须在实际实现中安排驻留评测或评测完成后退役，当前尚未接通。可恢复记录不等于可断点恢复训练。
