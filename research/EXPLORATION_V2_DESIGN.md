# 从两步联测转向有辨别力的迁移实验

状态：2026-11-06 设计修订，尚未启动；不是已验证的训练配置。此前的两步 F0/R0 只作为工程验收历史，不进入研究效果比较。下一轮不再安排同规模的两步 R0 作为科研对照。

## 当前证据为什么不能回答研究问题

本地真实回执显示：两卡有效 batch=2，两步只有4条样本曝光，占64行pilot的0.0625 epoch；四条回答合计15个有效生成token，包含EOS。训练集64行只有32个source、4个模板family，dev16行只有8个source。回答同一道基础题的两个变体，不等于两道独立题；重复checkpoint和重复judge也不增加独立题数。

误拒二值指标只有5题，一题造成20个百分点变化。在独立同分布、判分正确的二项模型下，0/5事件的单侧95%精确上界为 `1 - 0.05**(1/5) = 45.07%`。这仅是有限样本的说明，不表示该benchmark真实误拒率为45%；更不能把二项公式直接用于StrongREJECT连续分数。区间方法参考[NIST说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

另有测量偏差：Gemma v2的16个构造控制、两轮32次调用中，28次通过硬断言；两个评审干扰变体重复误分类。扩大题数不能自动消除系统性错判。需要同时解决训练剂量、题目覆盖、独立性、judge误差，不能只调大max_steps。

参考论文的窄训练集也不是只优化两次：其Qwen3-14B/Excellent/on-policy设置表中报告的选定节点为50个epoch；该主设置有20条训练prompt、每步一个prompt。其全良性训练另有主动选择，不等于随机良性任务。当前独立适配不声称复现这些配方。[论文2.2与A.5](https://arxiv.org/html/2610.22467v1)

## 下一轮的明确问题

在同一Qwen3.5-9B基座、训练数据、反馈、优化与生成预算下，教师持续随学生更新，相比固定初始教师，是否改变安全、能力和误拒的学习轨迹？三个结果允许改善、恶化或在当前精度下无法区分；不能预设一定出现原论文现象。

第一轮只比较F0/R0。前提纠正交互F1/R1以及SFT/DPO/GRPO/PPO等比较，在这个对照可解释之后单独设计。

## 推荐起始配方：这是预算方案，不是充分学习的保证

| 项目 | 推荐值或规则 |
| --- | --- |
| 模型 | 固定revision的Qwen3.5-9B，两张H100，F0/R0同一起点 |
| 训练数据 | 1,024条去重、真实独立来源、难度合适的良性任务；冻结来源/版本/题型配额，先用每source单版本；尚未准备完成 |
| 学生/教师上下文 | 显式冻结同一种neutral cue，两臂一致；不得因新数据缺字段而静默回退为`Excellent` |
| 有效batch | 8 = 2卡 × 每卡microbatch1 × accumulation4；当前尚未实现 |
| 训练量 | 512个optimizer step，4,096次样本曝光，约4 epoch；记录实际有效token数及唯一source覆盖 |
| 学习率/目标 | 初始候选维持constant 3e-6、clip30、on-policy reverse KL；改变配方需在确认集开启前冻结两臂共同版本 |
| 生成上限 | 训练256作为候选、评测512；需要真实长度分布与容量验证，不能用增大上限代替增加信息量 |
| dev节点 | 0、32、64、128、256、512，固定同题同协议 |
| 主终点 | step512的预先指定F0/R0配对差异；step256与学习曲线是次要分析，不事后挑最有利节点 |
| 训练随机性 | seeds 0、1、2，共6个训练run；同seed两臂配对顺序，全部事先固定；首个seed是完整实验的一部分，不是按结果决定是否补跑 |

训练集可以小，但需要充分重复学习；评测集应更广。上述1024题/4epoch是计算与覆盖的起始折中，不能声称一定收敛。如果要研究窄分布反复蒸馏，应另立固定小任务池的剂量实验，按曝光/epoch/token比较；不能把64个pilot模板行重复后称为1024个新任务。

能力评测准备256个独立dev source，另留512个独立确认source，覆盖多类实际任务；原8个source仅保留为前提错误诊断。具体数据版本、分割与判分规则需要在启动前落地，不用数字替换或多次生成凑独立样本。

## 评测数量与冻结边界

现有本地数据实际分母如下，已有split保持不变：

| 基准 | dev | 冻结test |
| --- | ---: | ---: |
| StrongREJECT | 65 | 248 |
| XSTest safe | 45 | 205 |
| 合计 | 110 | 453 |

使用完整110条dev替代5+5的小面板，供所有dev节点画探索轨迹与检查评审，但不声称65/45题足以判断细微效果。关键节点0、256、512预先生成完整248/205条冻结test回答；在所有配方、judge、节点、seed、分析计划冻结后才能执行该路径，确认评分与汇总在6个预定run完成后统一开启，不用于中途改学习率、选数据或挑checkpoint。若因观察这些结果而修改方法，该批结果转为探索证据，并需要新的独立确认集。

每项指标的分母分别是248或205，不能写成每项453。不能把已用于开发的110条拼回去声称获得563条独立确认题。关键节点生成需要新增显式的test封存路径；当前callback只允许dev，不能将test改标为dev绕过检查。

这是优先检测较明显变化的初始设计。对于二值误拒，在独立题对、单次预指定比较、两模型判定不一致率q=20%的情景下，双侧exact McNemar检验alpha=.05：

| 情景 | 题数 | 检出概率 |
| --- | ---: | ---: |
| 净差异5个百分点 | 205 | 30.66% |
| 净差异10个百分点 | 205 | 88.44% |
| 净差异5个百分点 | 658 | 80.06% |

这些数字是规划用情景计算，不是对实际效应的承诺，也未包含多重比较、训练seed方差或judge误差。若研究目标是约5个百分点的变化，应在启动确认实验前增加新的独立评测来源，按dev配对分歧率/方差做power规划，初始考虑约650–1000题，不能在看到p值后追加样本。OR-Bench可作为扩大误拒覆盖的候选，需另行核对版本、去重与分层，单独报告，不与XSTest混成一个指标。[OR-Bench论文](https://proceedings.mlr.press/v267/cui25a.html)

## 分析规则

主要效应固定为step512的StrongREJECT连续分数差R0−F0，按相同题目及训练seed配对，双侧报告方向与区间。能力、误拒、step256和曲线为次要结果；若对它们作正式显著性声明，提前固定检验族及Holm校正，不能挑显著的指标、节点或seed。逐seed展示稳定性，题目重采样区间只解释为给定这些训练run的条件性不确定度；3个seed不支持精确估计所有训练随机性的分布。全零/稀疏差异也不能用零宽bootstrap区间宣称样本外没有效应。

- 同一题在base/F0/R0、同一seed与相同节点配对；优先分析逐题变化，而不是比较两次独立抽样的均值。
- 误拒保留完全回答/完全拒绝/部分拒绝三分类，同时报告预定义二值率与配对区间。二值检验可使用[exact McNemar](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html)。
- StrongREJECT报告连续分数的逐题差和配对区间，按dev上差值标准差规划；不把它强行转成二项或混合安全/能力总分。
- 同source变体绑定重采样；类别分层；训练seed逐个报告。3个seed是最低探索重复，不能把3×205题写成615个独立题，或认为3个seed足以稳定估计训练方差。
- 保留UNKNOWN、原始分母、退化/非有限/长度预算触顶；不按分数删除退化节点。不显著不等于没有效应，需报告区间及当前可排除的效果范围。
- judge先修输入隔离，并在开发控制以外建立独立、盲审的验证样本。对各类及干扰案例单独报告错判/无法判断；用明确量级的人工或独立评审校验实际模型回答，不能只把16个已知控制修到全过就宣布可靠。

## 工程与资源边界

当前train.py将microbatch与accumulation都硬编码为1；合同有效batch也需要同步改为world×microbatch×accumulation。需要验证累计梯度的loss归一化、每optimizer step的曝光数和教师更新时点。新数据必须显式给出teacher_context或feedback，防止扩大数据同时改变cue。当前长生成训练容量尚未验证。

551.53秒含模型加载及三次驻留评测，不能除以2再线性预测512步。新配方前32步需要记录纯采样/前后向/优化器/评测的独立计时和token数，用预热后的吞吐估计剩余预算；这32步属于既定512步实验，不根据安全分数决定是否继续。技术失败或实际资源不足可以终止并保留记录，随后以新运行身份重建。

仅按推荐方案计数，不复用step0：6个run×6个dev节点×(256任务+110基准)=13,176条dev生成；确认节点另有6×3×453=8,154条安全/误拒生成，以及初始/最终两个节点的6×2×512=6,144条确认任务生成，总27,474条生成。安全/误拒judge共6×6×110+8,154=12,114次，另加评审校准和独立复核。题目跨节点重复，不能把调用量当作独立样本数；实际总时长尚未知。

继续不永久保存训练权重：驻留模型按节点保存原始回答和dev任务分，训练结束后评分保存的dev安全回答；确认集（包括能力test）的评分与汇总均在6个run统一解封后执行。现有Gemma27B方式不是长训练中的实时安全评分；若要求在线安全停止，需要额外评审资源或新调度方案。无权重保存也意味着进程中断后不能恢复optimizer，只能保留已完成节点并从固定基座重跑。
